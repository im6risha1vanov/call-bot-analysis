# Модель разбора: GPT-6.1 Sol

2 октября 2026 владелец запросил переключение модели разбора на 6.1-sol.
Рабочая настройка сервера: `CVC_MODEL=gpt-6.1-sol` в закрытом `.env`.
Сохранён `CVC_REASONING_EFFORT=high`, endpoint Responses, промты, выходные схемы,
лимиты ответов и дневной бюджет. Код моделей-клиентов менять не требуется:
`analysis.MODEL` используется исходным анализом и подробным разбором, оценкой
курса и настройками новых объединённых разборов.

Старые сохранённые отчёты и закреплённые эксперименты А/Б не пересчитываются.
Созданные ранее задания с закреплённой моделью продолжают использовать свои
исходные параметры; при переключении автоматических закреплённых заданий не было.
Для новых объединённых разборов модель закрепляется из новой настройки.

Официальный ID и совместимость `high` проверены по
[OpenAI Docs](https://developers.openai.com/api/docs/models/gpt-6.1-sol).
Первичная проверка `/models` вернула HTTP 402; недавние задания на старой модели
также имеют 402. После переключения один короткий синтетический запрос к
`/responses` успешно получил HTTP 200 и `model=gpt-6.1-sol` (38 токенов всего).
Таким образом, новый ID принят провайдером. Полный производственный разбор этим
тестом не проверен; точная причина прежних 402 не установлена.
Оценочный коэффициент кредитных единиц оставлен прежним: официальный долларовый
тариф не подтверждает биллинг стороннего провайдера.

Секреты в Git не помещаются. Закрытая резервная копия конфигурации находится вне
репозитория в `/opt/callbot-astra-backups/model-sol-20261002/` с доступом только root.
Применение требует перезапуска основного бота и очереди после завершения активных
заданий. Опрос Mango и клиент тренажёра не нуждаются в перезапуске.

Настройка подтверждена в окружении обоих запущенных процессов. С подменённым
HTTP проверены тела запросов исходного, курсового и объединённого разбора:
все используют `gpt-6.1-sol`, `high` и свои прежние лимиты выхода. Все четыре
службы активны. Сохранённые результаты, история и очередь не пересчитывались.
